# PreviewLog 랜딩페이지 사용자 관점 검토

- 검토 대상: `deploy/index.html`
- 검토 기준: 출시 전 랜딩페이지, macOS 앱 사용자, 대기자 등록 전환
- 검토일: 2026-09-30
- 상태: 수정 전 검토안

## 총평

현재 페이지는 PreviewLog가 무엇을 하려는지 설명하지만, 사용자가 실제로 등록하거나 설치를 결정할 만큼의 증거와 신뢰는 부족하다.

현재 상태는 출시 페이지라기보다 **제품 콘셉트와 출시 대기자 모집을 위한 소개 페이지**에 가깝다.

## P0 — 출시 전에 반드시 해결

### 1. CTA와 실제 행동이 불일치

히어로의 `무료로 시작하기`는 다운로드 섹션으로 이동하지만, 실제 설치파일은 없다. 사용자는 무료로 앱을 시작할 수 있다고 기대했다가 막힌다.

권장 변경:

- `무료로 시작하기` → `출시 알림 받기`
- 또는 `체험판 출시 알림 받기`

### 2. 대기자 등록 폼이 실제로 연결되어야 함

`deploy/index.html`의 대기자 등록 폼은 `data-endpoint=""` 상태다. 이 상태에서는 이메일을 입력해도 Google Sheet에 저장되지 않고 “대기자 등록 연결을 준비 중입니다.”라는 메시지만 표시된다.

필요 작업:

- Google Apps Script Web App `/exec` URL 연결
- 테스트 이메일 등록
- Google Sheet 기록 확인
- 중복 이메일 테스트
- 잘못된 이메일·동의 누락·스팸 입력 테스트

### 3. 개인정보 수집 안내 부족

현재 폼은 이메일, 이름, 플랫폼을 수집하고 Apps Script는 페이지 URL과 User-Agent도 기록한다. 하지만 화면에는 이메일 수신 동의만 있고 다음 정보가 없다.

- 수집 항목
- 수집 목적
- 보유 기간
- 삭제 요청 방법
- 발송 주체
- 수신 거부 방법
- 개인정보 처리방침 링크

실제 공개 전 개인정보 처리방침과 동의 문구를 일치시켜야 한다.

### 4. 법적·운영 정보 부족

푸터에 다음 문서와 정보가 없다.

- 개인정보 처리방침
- 이용약관
- EULA
- 환불·구독 정책
- AI 기능 고지
- 사업자 정보
- 실제 고객지원 이메일
- 오픈소스 고지

사업자 정보가 확정되기 전에는 임의의 값을 공개하지 않는다.

### 5. 실제 제품 증거 부족

히어로의 앱 화면은 CSS 목업이다. 실제 사용자는 다음을 확인할 수 없다.

- 실제 앱 UI인지
- 실제 분석 결과인지
- 한국어 전사 품질
- 컷 검출 품질
- 장면 설명 품질
- 편집자가 받는 결과물의 형태

실제 스크린샷을 아직 넣지 못한다면 최소한 다음을 제공한다.

- 실제 결과 파일 샘플
- 한국어 전사 샘플
- HTML 프리뷰 샘플
- SRT·CSV 샘플
- 분석 전·후 예시

## P1 — 전환율 개선

### 1. 분석 속도

1시간 촬영본을 얼마나 걸려 처리하는지 정보가 없다. 로컬 분석 앱에서 처리 속도는 핵심 구매 판단 요소다.

측정 전에는 다음처럼 안내한다.

> 처리 시간은 영상 길이, 해상도, Mac 사양과 선택한 모델에 따라 달라집니다.

이후 실제 Mac 사양별 벤치마크를 추가한다.

### 2. 편집툴 연동

현재 `SRT · VTT · CSV`만 노출되어 있다. 다음 정보를 명시해야 한다.

- Premiere Pro 마커 지원 여부
- DaVinci Resolve 마커 지원 여부
- Final Cut Pro 지원 여부
- XML·EDL 지원 여부
- 타임코드가 원본 기준인지 프록시 기준인지

### 3. 한국어 전사·장면 설명

앱 목업의 장면 설명이 영어로 표시된다.

> Two people talking in a bright interview setting.

한국어 앱에서 결과도 영어인지 오해할 수 있으므로, 실제 지원 언어와 결과 언어를 명시한다. 가능하면 한국어 결과 샘플을 보여준다.

### 4. 체험판과 유료 기능 차이

가격표에는 체험판과 연간 구독의 기능 차이가 없다. 다음을 설명해야 한다.

- 체험판에서 사용할 수 있는 기능
- 5시간 제한의 기준
- 체험판 결과물의 제한 여부
- 워터마크 여부
- 구독 만료 후 기존 프로젝트 열람 가능 여부
- 신규 분석·내보내기 제한 범위

### 5. 실사용 근거

현재 사례·후기·베타 사용자 근거가 없다.

추가 후보:

- 조연출·프리뷰 작가의 사용 사례
- 인터뷰·다큐 촬영본 예시
- 베타 사용자 한 줄 후기
- 분석 전후 작업시간 비교

## 메시지와 신뢰의 모순

### 로컬 처리와 인터넷 사용

“클라우드 업로드 없이”라고 말하면서 인터넷 필요 항목은 아래쪽에 있다. 다음 문장을 상단에 함께 표시하는 것이 좋다.

> 영상·오디오·전사·컷은 서버로 보내지 않습니다. 계정·라이선스·업데이트 확인에는 인터넷이 필요합니다.

### Apple Silicon 지원 표현

페이지는 M1 이상 지원이라고 안내한다. 실제 앱 빌드·성능·Rosetta 사용 여부가 확정된 내용과 일치하는지 확인해야 한다.

### Windows 지원

“Windows 준비 중”은 일정이 없는 상태에서 약속처럼 읽힐 수 있다. 확정 전에는 다음처럼 완화할 수 있다.

> Windows 지원은 검토 중입니다.

### 가격 정보

현재 가격은 `₩120,000 + VAT`로 표시된다. 한국 사용자에게는 실제 결제액을 함께 보여주는 편이 이해하기 쉽다.

> 연 120,000원 + VAT / VAT 포함 132,000원

단, 실제 Paddle 설정과 일치할 때만 표시한다.

## 카피 개선안

현재 H1:

> 촬영본을 편집 가능한 로그로.

추천안:

> 촬영본을 정리해<br />편집자에게 바로 넘기세요.

또는:

> 조연출과 편집자를 위한<br />촬영본 정리 도구.

`고유 원본 5시간`은 내부 용어처럼 느껴진다.

추천 문구:

> 14일 또는 분석한 촬영본 5시간 중 먼저 도달하는 시점까지

## UX·접근성 검토

### 좋은 점

- 문제 → 기능 → 사용 방법 → 결과물 → 요구사항 → 가격 순서가 자연스럽다.
- 로컬 처리와 개인정보 보호 메시지가 명확하다.
- 모바일 메뉴에 `aria-expanded`와 `aria-controls`가 적용되어 있다.
- 시스템 요구사항과 지원 포맷이 구체적이다.

### 개선점

- 페이지가 길어 핵심 CTA가 중간에 묻힌다.
- 영문 키커가 많아 한국어 사용자에게 템플릿처럼 느껴질 수 있다.
- 목업 내부 텍스트가 작고 실제 결과처럼 보여 오해를 만들 수 있다.
- 모바일 앱 목업 내부의 6–8px 텍스트는 읽기 어렵다.
- 보조 텍스트 일부는 대비가 약하다.
- 페이지 언어는 한국어지만 앱 목업·결과 텍스트는 영어가 섞여 있다.

## 기술·SEO 체크

- `meta description` 없음
- Open Graph 제목·설명·이미지 없음
- favicon 확인 필요
- 실제 대기자 등록 endpoint 미설정
- 폼 전송은 `no-cors` 방식이므로 서버 응답의 성공·실패를 정확히 읽지 못함
- `User-Agent`와 페이지 URL 수집에 대한 고지 필요
- 공개 배포 시 `deploy/` 내부 경로와 브랜드 에셋 경로 확인 필요

## 권장 실행 순서

### 1단계 — 공개 전환 가능 상태

1. `무료로 시작하기`를 `출시 알림 받기`로 변경
2. Apps Script `/exec` URL 연결
3. 실제 Google Sheet 기록 확인
4. 개인정보 수집 안내 추가
5. 정책·사업자·지원 정보 추가
6. M1·Windows 지원 범위 확정

### 2단계 — 제품 신뢰성

1. 실제 처리 속도 측정
2. 한국어 전사 샘플 추가
3. Premiere·Resolve 연동 범위 명시
4. 결과물 샘플 제공
5. 체험판과 유료 기능 차이 명시

### 3단계 — 완성도

1. 실제 앱 화면 또는 데모 추가
2. 베타 사용자 사례 추가
3. SEO·OG 태그 추가
4. 모바일 목업 텍스트 확대
5. 영문 키커와 결과 텍스트 정리

## 결론

현재 페이지의 핵심 문제는 디자인보다 사용자가 다음에 무엇을 할 수 있는지가 불명확하다는 점이다.

현재 흐름:

> 제품 소개 → 무료로 시작하기 → 다운로드 섹션 → 설치파일 없음 → 대기자 폼 → endpoint 미연결

목표 흐름:

> 제품 이해 → 실제 결과 신뢰 → 출시 알림 등록 → 개인정보·운영 주체 확인 → 등록 완료

가장 먼저 해결할 파일 위치는 다음과 같다.

- `deploy/index.html:32` — CTA 문구와 목적지
- `deploy/index.html:83` — 대기자 등록 폼
- `deploy/main.js:44` — endpoint 미설정 처리
- `apps-script/Code.gs` — Google Sheet 수집 및 개인정보 고지 정합성
